Jam tracks how AI assistants answer the questions your buyers ask, and turns the gaps into a Plan of actions. Everything a customer does in the dashboard is available to an agent through the REST API at `https://api.spreadjam.com/v1` and the MCP server at `https://api.spreadjam.com/mcp`.

Jam scans ChatGPT, Gemini, Perplexity, Google AI Mode, Google AI Overviews and Microsoft Copilot.

## 1. Get an API key

<Tabs>
  <Tab title="From an agent (agent connect)">
    The agent starts a session. No key is needed for this call.

    ```bash
    curl -sS -X POST https://api.spreadjam.com/v1/agent-connect \
      -H "Content-Type: application/json" \
      -d '{"domain": "acme.com", "agentName": "Claude Code"}'
    ```

    ```json
    {
      "connectUrl": "https://www.spreadjam.com/connect/ABCD234567",
      "userCode": "K7M-Q2X",
      "pollToken": "jcp_...",
      "expiresAt": "2026-11-04T12:00:00.000Z",
      "intervalSeconds": 5
    }
    ```

    `agentName` is optional (1 to 60 printable characters; without it the page says "Your agent"). `domain` is optional and must be a website hostname such as `acme.com`. Anything else is a `400 invalid_request` whose `details` names the field.

    Give the human the `connectUrl` and the `userCode` together, for example: "Open this link and check that it shows the code K7M-Q2X." The approval page shows the same code, the email they are signed in with and the workspace the key will belong to (they can switch to another of their workspaces there). They sign up or sign in, set up their site (the domain you sent is filled in), choose a plan, and approve. If they already use Jam, they only approve. After they approve, the page tells them to return to you while you finish connecting.

    Keep the `pollToken` secret, and poll every `intervalSeconds`:

    ```bash
    curl -sS https://api.spreadjam.com/v1/agent-connect/$POLL_TOKEN
    ```

    | `status` | Meaning |
    | --- | --- |
    | `pending` | The human has not approved yet. Poll again. |
    | `approved` | The response carries `apiKey` and `workspaceId`. This is the only time the key is shown: store it now. |
    | `consumed` | The key was already handed out. Start a new session if it was lost. |
    | `denied` | The human declined. |
    | `expired` | Nobody approved within two hours. Start a new session. |

    Starting sessions is limited to 10 per IP address every 10 minutes.
  </Tab>
  <Tab title="From the dashboard">
    1. Open Jam and go to **Settings**, then **Developer**.
    2. Click **Create API key** and give it a name.
    3. Copy the key. It is shown once.
  </Tab>
</Tabs>

Keys look like `sk_` followed by 64 hex characters. A key reaches its workspace's real data; there are no test keys. It can read everything in the workspace and make the changes its creator can make in the dashboard, including work that spends credits; it acts with its creator's role, so a member's key cannot do owner-only things such as managing billing. Revoke a key in **Settings**, **Developer** (a key can also revoke itself with `DELETE /v1/api-keys/{keyId}`).

## 2. Connect over MCP

The MCP server exposes every API route as a tool, named by its operation id (`get_me`, `list_prompts`, `list_actions`, ...). It uses the same key.

<CodeGroup>
```bash Claude Code
claude mcp add --transport http jam https://api.spreadjam.com/mcp \
  --header "Authorization: Bearer $JAM_API_KEY"
```

```json Cursor (.cursor/mcp.json)
{
  "mcpServers": {
    "jam": {
      "url": "https://api.spreadjam.com/mcp",
      "headers": { "Authorization": "Bearer sk_..." }
    }
  }
}
```
</CodeGroup>

Tools are annotated, so your client can auto-approve the safe ones and ask before the rest:

- Reads are `readOnlyHint: true`.
- Tools that spend credits, publish to your site or repository, or delete something are `destructiveHint: true`. A tool that spends credits says what it costs at the start of its description (for example `create_research_request`: "Costs 500 credits (the first research run is free).").
- Tools that are safe to repeat are `idempotentHint: true`.

Tools a key can never use (creating API keys, the key-less agent-connect calls) are not listed.

To work on a project other than your newest one, pass `projectId` (an id from `list_projects`) to any project tool, or send `X-Jam-Project: <projectId>` with the MCP connection. The argument wins for that one call.

Prefer plain HTTP? Use the [OpenAPI spec](https://api.spreadjam.com/openapi.json) and send `Authorization: Bearer $JAM_API_KEY` on every request.

## 3. Your first five calls

```bash
export JAM=https://api.spreadjam.com/v1
auth=(-H "Authorization: Bearer $JAM_API_KEY")

curl -sS "${auth[@]}" $JAM/me                  # which workspace this key is for
curl -sS "${auth[@]}" $JAM/analytics/overview  # visibility, mentions, citations
curl -sS "${auth[@]}" $JAM/prompts             # what is tracked
curl -sS "${auth[@]}" $JAM/actions             # the Plan: what to do next
curl -sS "${auth[@]}" $JAM/credits             # credits left and when they reset
```

Over MCP these are `get_me`, `get_analytics_overview`, `list_prompts`, `list_actions` and `get_credits`.

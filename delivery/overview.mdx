A drafted page stays in Jam until it is delivered. Choose one delivery method per project:

<CardGroup cols={2}>
  <Card title="GitHub" href="/delivery/github">
    Jam opens a pull request on your site's repository. You review and merge.
  </Card>
  <Card title="Markdown" href="/delivery/markdown">
    Get each article as a Markdown file to publish yourself, or hand it to your
    agent.
  </Card>
</CardGroup>

Until you choose, the Plan shows both options once: **Use Markdown** or **Connect GitHub**. You can change it later in **Settings**.

## What is delivered

- **New pages** (`new_page` actions): the article, as a draft you can read, edit and request changes to first.
- **Page edits and technical fixes**: a prepared code change. These need GitHub; with Markdown delivery, copy the action's prompt to your coding agent instead.

Nothing is sent to your site without a request: the drafts Jam writes after the first research run stay in Jam until someone publishes them.

## Where a page is live

Once a page is published, `list_content_publications` shows where it is live. If you published it yourself, record the URL with `mark_content_published` (**Mark published**). To have Jam check the page for the action, report the action done with the URL (see [Doing the work](/actions/doing-the-work)).
